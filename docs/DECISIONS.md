# Decisions — G5 Vault Gardener

Every call made in this build, numbered. **Provisional** means the owner (Shane) has not confirmed it; the build ran unattended on 2026-11-21 and took the PRD's recommendation or the owner's run instructions. Nothing here is a client result: this is a portfolio sample build on a synthetic vault and hand-written recorded model responses.

| # | Date | Decision | Why / options considered |
|---|---|---|---|
| D-1 | 2026-11-21 | **The vault is synthetic.** `fixtures/vault/` holds 63 made-up Obsidian-style notes in five folders (`projects/`, `reference/`, `ideas/`, `logs/`, `inbox/`), plus `fixtures/arrivals/` (inbox items and user edits that "arrive" during the simulated day), a synthetic tag taxonomy (`fixtures/taxonomy.json`) and a hand-labeled sample of 20 notes (`fixtures/labels.json`). No real people, companies or personal content. The worker only ever runs against a temporary **copy** of this fixture vault: `gardener copy-fixture` writes a `.gardener-copy` marker, and the worker refuses any vault without that marker or any path inside `fixtures/` (D-20). PRD decision 1 ("a copy of your Lab vault") is deferred to the owner. | Owner's call 2026-11-21 (public repo). Answers PRD question 3: no personal notes ship. |
| D-2 | 2026-11-21 | **Build only G5·C** (Python 3.12 + Claude Agent SDK worker). G5·B (n8n) is skipped; the owner builds n8n versions by hand. KICKOFF's "B first, C after B passes" and "stop after the plan" are overridden: `docs/BACKLOG.md` was written, then the whole backlog was built. Branch `build/g5c` (not `kickoff`). | Owner's standing instruction for this run. |
| D-3 | 2026-11-21 | **Inbox = the vault's `inbox/` folder**, no Gmail. Inbox items are processed like any note (tagged, typed, linked); the Classifier's folder suggestion for them is recorded, not acted on (D-13). | PRD recommendation 2 (Gmail adds permission and privacy risk to a public demo). |
| D-4 | 2026-11-21 | **Provisional — daily cost cap and token budget are configurable** (`--daily-cap-usd`, `--daily-token-budget`, or `G5_DAILY_CAP_USD` / `G5_DAILY_TOKEN_BUDGET`). Defaults are derived from the recorded 96-tick simulated day: **3× its estimated cost and tokens, rounded up** (values in `config.py`; a test re-derives them from a fresh simulation so they cannot drift silently). The recorded day's tokens are an estimate (D-9), so the defaults are placeholders until a measured live day. G0's own $10 per-run cap still applies on top (D-16). | PRD recommendation 3: set the cap after a measured day. No live day was possible ($0 run), so the recorded day stands in and the default is marked provisional. 3× headroom: a normal day stays far below it; a runaway prompt crosses it quickly (AC2). |
| D-5 | 2026-11-21 | **Provisional — the Linker writes** a managed "Related" section on the copy vault. `--suggest-only` makes it write the same links to `<state>/suggestions.jsonl` instead and leave notes untouched. Shane to confirm write vs suggest before any non-copy vault. | Owner instruction for this run (PRD question 1 still open). |
| D-6 | 2026-11-21 | **Tag taxonomy = the synthetic one** in `fixtures/taxonomy.json` (9 `topic/*` tags, 3 `status/*` tags; 5 note types; a type→folder map). A model tag outside the taxonomy is dropped and logged (`tags_rejected`), never written. A type outside the list is a malformed response (error). | Owner instruction (PRD question 2 answered for the synthetic vault). |
| D-7 | 2026-11-21 | **Attached to G0 at `6f5e605f8b485afa95f1cbef73911057b8b4dec5`** (g0-shared-layer `main`), pinned as a git dependency in `pyproject.toml` exactly as G3·C does. Capabilities are called in-process through one adapter (`src/vault_gardener/layer.py`, modelled on G3's). `health` is called first; a degraded layer or a missing G5 rubric stops the worker. Used: **observability** (every agent call: tokens, cost, run total), **measurement** (`vault_gardener.tick`, `vault_gardener.supervisor_tripped`, `vault_gardener.daily_report`), **evaluation** (labeled-sample quality). No rule from G0 is copied into a prompt. | Owner instruction. G0 is read-only for this build. |
| D-8 | 2026-11-21 | **Labeled-sample rubric through G0's seed loader.** G0 `evaluation` v1 has no rubric-register tool and no note-labelling rubric. As G2/G3 do (G3 D-7), the rubric `g5_note_labels_v1` lives in `rubrics/` and is loaded into G0's store with G0's own idempotent loader; the adapter refuses ids not namespaced `g5_`. Per labeled note, G5 builds an item `{type_match, tags_recall, tags_precision, links_precision}` (each `full`/`partial`/…) and G0's `DeterministicJudge` + `decide()` give pass/fail. The aggregate precision/recall figures are arithmetic over the same comparisons, computed in `quality.py`. | Options: (a) add a rubric to G0 (not allowed here), (b) score entirely in G5 (moves the pass rule out of G0), (c) seed through G0's loader — chosen, the documented exception. A `rubric.register` tool stays a G0 follow-up. |
| D-9 | 2026-11-21 | **Recorded model path only; $0 spend.** `RecordedCaller` answers from `fixtures/recorded.json`, which is **hand-written** in each agent's output shape (with designed mistakes, D-24) — not a recording of a live model. `AgentSdkCaller` (Claude Agent SDK `query`, structured output, no tools) sits behind the same `ModelCaller` interface but is never run: it refuses to construct without `ANTHROPIC_API_KEY`, and `--live` refuses without the key. Because recorded responses have no usage block, **tokens are estimated** as ⌈characters / 4⌉ of prompt and response and priced with G0's price table; every report labels them "estimated, recorded fixtures". Confirmed 2026-11-21 on Anthropic's models overview and pricing pages: `claude-haiku-5-5` ($0.10 / $0.50 per MTok up to 100K-token prompts), `claude-sonnet-5-5` ($2 / $10), `claude-opus-5-5` ($4 / $20) — matching G0's `PRICES_PER_MTOK`. PyPI: `claude-agent-sdk` latest **0.2.187** (2026-11-20); pinned `>=0.2.187,<0.3`. `opentelemetry-sdk` 1.45.2. | Owner instruction. Without estimated tokens the cost supervisor could never be exercised on the recorded path; the estimate is labeled wherever it appears. |
| D-10 | 2026-11-21 | **Provisional — Classifier and Linker both use `claude-haiku-5-5`.** Tagging a note and picking related notes from a candidate list are short, structured tasks run every 15 minutes all day; Haiku is the cheapest confirmed model. Configurable per agent (`G5_CLASSIFIER_MODEL`, `G5_LINKER_MODEL`). | Cost of a continuous job. A measured quality comparison with Sonnet is a later step. |
| D-11 | 2026-11-21 | **What "note body" means.** A note is optional YAML frontmatter (`---` … `---`) plus the body. The Linker's section is a managed block appended at the end, between `<!-- gardener:related:start -->` and `<!-- gardener:related:end -->`, preceded by exactly two newlines. **Body = everything after the frontmatter with the managed block (and those two newlines) removed.** Its SHA-256 must be identical before and after every agent write and across every tick. A user's own "## Related" heading is body and is never touched. | Makes "never rewrite a body" a byte-exact, testable check, and makes the Linker's block removable without trace (revert is byte-identical). |
| D-12 | 2026-11-21 | **Frontmatter edits are line-based and limited to `tags` and `type`.** Every other frontmatter line stays byte-identical, in order. Tags are a **union**: the agent adds taxonomy tags, never removes or rewrites a user's tag. `type` is set only when missing; a different suggestion for an existing type is recorded, not written. A note without frontmatter gets a new frontmatter block containing only `tags`/`type`. `safety.check_change(before, after)` enforces all of this and runs inside the writer before every write; a violation is refused and trips the supervisor (`safety`). | PRD: agents may edit frontmatter and append Related, nothing else. Tag union + set-if-missing keeps agents from overruling the owner. |
| D-13 | 2026-11-21 | **Folder suggestions are recorded, never acted on.** Moving a file deletes it from its old path, which the safety rules forbid. The Classifier's `folder` is stored in the state table and shown in the report ("inbox items with a folder suggestion"). | PRD's Classifier "suggests a folder"; the write rules allow only frontmatter + Related. |
| D-14 | 2026-11-21 | **Row locks = leases in the SQLite state table** (`notes.lock_owner`, `lock_expires`), taken with `BEGIN IMMEDIATE` + a conditional `UPDATE`, released in `finally`; expired leases (120 s of clock time) can be taken over. WAL mode, one connection per agent/thread/process. **Plus compare-and-swap on the file**: the writer re-reads the file under the lock and writes only if its hash equals the hash the agent based its edit on; otherwise the write is skipped as `conflict` and retried next tick. Change log rows are written `pending` before the file write and marked `applied` after (two-phase), so a crash can be reconciled at start-up. | AC4. Locks alone fail if a lease expires mid-write; CAS alone can lose work silently. Both, and a test for each layer. |
| D-15 | 2026-11-21 | **Supervisor limits** (all configurable): daily cost cap and token budget (D-4), checked before and after every model call; **error burst = 5 errors within 60 minutes of clock time** (`--error-burst`, `--error-window-min`); any safety-check refusal trips at once. A trip sets the **kill switch** in the state table, writes an alert line to `<state>/alerts.log` (no external send) and a G0 `measurement` event, releases every lease, leaves in-flight notes at their last committed status, and stops the loop. The switch persists across restarts until the owner runs `gardener resume`. `gardener kill` sets it by hand; a running worker sees it before its next model call. | PRD: supervisor stops the job past limits; kill switch leaves the state table consistent. `state.check_consistency()` defines "consistent" and is asserted after every trip. |
| D-16 | 2026-11-21 | **Cost accounting.** Every agent call is logged to G0 `observability` with `run_id = g5-<UTC date>` so G0's `run_total` is the day's running total (the supervisor reads it), `step = t<tick>.<agent>`. Per-tick totals live in G5's own `runs` table. Days roll over at 00:00 UTC. | One place (G0) holds the cost ledger; the supervisor does not keep a second copy. |
| D-17 | 2026-11-21 | **Change log stores the whole file before and after** (plus hashes, agent, tick, run). `gardener revert --run <id>` or `--all` restores changes newest-first, only when the file still equals the logged "after" (otherwise reported as a conflict and left alone), and logs each revert as its own change. | PRD: every change logged before/after so any run can be reverted. Whole-file snapshots make the revert byte-exact; notes are small. |
| D-18 | 2026-11-21 | **OpenTelemetry** via `opentelemetry-sdk`: one span per tick (`gardener.tick`), children per agent stage and per agent call (`gardener.classifier.call`, …) with tokens, cost, note path and recorded key; a supervisor trip is a span event. Exported with the SDK's console exporter pointed at `<state>/traces.jsonl` (one JSON span per line). No collector, no network. A private `TracerProvider` per worker (not the global one) so tests and concurrent workers do not interfere. | Owner instruction: local export only. |
| D-19 | 2026-11-21 | **AC1 is proved by a time-compressed simulation**, not a wall-clock day: `gardener simulate --ticks 96` drives the worker with a simulated clock (15 min per tick = 24 h), applies scheduled inbox arrivals and user edits between ticks, and hashes every body before and after every tick. **A real 24-hour run was not done** (owner step in NEXT.md). | Owner instruction. |
| D-20 | 2026-11-21 | **Where things live.** State (SQLite `state.sqlite`, `traces.jsonl`, `alerts.log`, `suggestions.jsonl`, reports) goes in a `--state` directory outside the vault; the G0 database defaults to `<state>/g0.sqlite` unless `G0_DB_PATH` is set. The worker refuses a vault that lacks the `.gardener-copy` marker or resolves inside the repo's `fixtures/`. The watcher ignores dot-files and dot-directories. | Keeps the copy vault free of tool files and makes "never the fixture itself" a guard, not a habit. |
| D-21 | 2026-11-21 | **Malformed model output and call errors.** A response that fails its schema (non-JSON, wrong shape, type outside the taxonomy) or a caller exception is an error: logged to the `errors` table and G0 observability (`status=error`), counted by the supervisor, the note stays at its status and is retried next tick; after 3 failed attempts it is parked (`status=error`) until its content changes. Unknown related targets and self-links are dropped (`links_rejected`), not errors. | Keeps one bad note from tripping the error-burst limit by itself on a normal day, while a real burst (many notes failing) still trips. |
| D-22 | 2026-11-21 | **Tooling:** Python 3.12, `uv` with a lockfile, `ruff`, `mypy --strict` on `src/`, `pytest`; GitHub Actions CI runs lint, typecheck, tests, the 96-tick simulation and the quality report on push and pull_request (read-only token, no deploy). Kit files (`CLAUDE.md`, `KICKOFF.md`, `docs/prd.md`) unchanged; `NEXT.md` gets a dated section, original text kept. | Same as G3·C (G3 D-16, D-17). |
| D-23 | 2026-11-21 | **Agent order inside a tick:** Watcher (scan, mark new/changed) → Classifier (all pending) → Linker (all classified). A note changed by the owner goes back through both. One tick processes everything pending; there is no per-tick note limit (the cost cap is the limit). | PRD agent table. A per-tick limit is easy to add if the first live day shows bursts. |
| D-24 | 2026-11-21 | **Designed imperfection in the recorded responses.** So the quality report and error paths mean something, the hand-written responses contain deliberate mistakes, listed in `fixtures/make_fixtures.py` (`CLASSIFIER_MISTAKES`, `LINKER_MISTAKES`): missing status tags, a wrong extra topic tag, a tag outside the taxonomy, a wrong type, one malformed response, cross-topic links and a link to a note that does not exist. The quality numbers are therefore a property of these fixtures, not of any model. | Owner: "no invented numbers". A perfect recorded run would be a number designed to look good. |
